# Berechtigungs-Onboarding als Neuimplementierung statt GPLv3-Code-Copy

**Kontext:** Issue #156 nimmt Fluid Voice als Vorbild für das interaktive Drag-&-Drop-Onboarding der Bedienungshilfen- und Eingabeüberwachung-Freigaben. FluidVoice ist GPLv3-lizenziert, Turbotext ist MIT. GPL-Code zu übernehmen würde das Gesamtwerk unter GPLv3 zwingen (Copyleft); ein Relicensing erfordert die Zustimmung aller Urheber (der Initial-Commit stammt von einem zweiten Contributor). Die verwendeten Techniken sind dünne Standard-APIs: `x-apple.systempreferences:`-Deep-Links, randloses nicht-aktivierendes `NSPanel`, SwiftUI-`onDrag` mit `NSItemProvider` (App-Bundle als Datei), TCC-Status-Polling (`AXIsProcessTrusted`, `CGPreflightListenEventAccess`).

**Entscheidung:** Spec-basierte Neuimplementierung: Das Verhalten wird aus FluidVoice extrahiert (Ablauf, Timings, Zustände, Edge Cases) und in Turbotexts Architektur eigenständig umgesetzt — keine Code-Kopie. Lizenz bleibt MIT; FluidVoice wird im README als Inspiration mit Lizenzhinweis genannt. Bewusste Abweichungen vom Vorbild: das Guide-Panel schwebt frei neben den Systemeinstellungen, statt das eigene Hauptfenster dorthin zu verschieben; nach einer Erteilung gibt es keinen Auto-Restart (FluidVoice startet einmal neu), weil CGEvent-Einfügen und globale Event-Monitore direkt nach der Erteilung wirken.

**Konsequenz:** Kein GPLv3-Einfluss auf das Projekt, voller Erststart-Komfort wie beim Vorbild. Der Credit im README ist Pflichtbestandteil des Issues. Ein späterer Lizenzwechsel zu GPLv3 bleibt als eigene Entscheidung möglich, erfordert dann aber die Zustimmung aller Urheber.
