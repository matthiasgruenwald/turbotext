# Rewrite-Backend wird vorab explizit gewählt, nicht per Laufzeit-Consent

**Kontext:** Die drei Rewrite-Workflows (Turbotext+, DampfAblassen, EmojiText) routen bisher über `RewriteRouter`: immer erst Apple-Gerätetranskription lokal, bei Kontextfenster-Überschreitung oder Guardrail-Verletzung ein Laufzeit-Consent-Dialog Richtung Online. Zwei Probleme: (1) Das On-Device-Modell schneidet bei längeren Diktaten Text ab, ohne dass der Validator (`RewriteOutputValidator`, ADR 0012) das immer erkennt — Nutzer bekommen unvollständigen Text ohne verlässliche Möglichkeit, das zu umgehen. (2) Der bestehende Schalter „Immer OpenAI für Umformulierungen" (`rewritingProviderMode: .auto`/`.immerOpenAI`) steuert nur, welcher Online-Anbieter im Consent-Dialog angeboten wird — er kann den Lokal-Versuch nicht abschalten, wie die Glättung es längst kann (`LiveSmoothingBackend`, ADR 0007).

**Entscheidung:** Rewrite bekommt dieselbe Struktur wie die Glättung: eine Dreiwege-Backend-Wahl (Aus / Lokal / Online), bei Online zusätzlich die bestehende, jetzt mit der Glättung geteilte Anbieter-Wahl (Groq / OpenAI, kein „Auto" mehr). Kein Laufzeit-Consent-Dialog mehr für Rewrite — die Einstellungswahl ist die Einwilligung, exakt das Prinzip aus ADR 0007. Im Detail:

- **Aus** — sofort Rohtext, kein LLM-Aufruf. Verhält sich wie das einfache Diktat ohne Glättung.
- **Lokal** — nur Apple on-device; jeder Fehler (Kontextfenster, Guardrail, Nichtverfügbarkeit) fällt still auf Rohtext zurück. Nie Richtung Online, auch nicht bei Fehler — die für Transkription depriorisierte „automatische Online-Eskalation" bleibt bewusst außen vor.
- **Online/Groq** — Groq zuerst; Anbieterfehler (Key, Rate-Limit) wechselt still zu OpenAI, kein Dialog — beide Anbieter sind datenschutztechnisch dieselbe Stufe („online verlässt das Gerät"), ein Nachfragen zwischen ihnen bringt keinen zusätzlichen Schutz. Zeigt `NetworkPingService.status == .red` einen echten Netzausfall an, wird stattdessen Lokal versucht (falls verfügbar), sonst Rohtext — dieselbe sichere Richtung (online→lokal), die `autoFallbackToLocalOnOffline` für die Transkription bereits nutzt.
- **Online/OpenAI** — nur OpenAI; Anbieterfehler geht direkt auf Rohtext (kein Groq-Ausweichen, das wurde nicht gewählt). `.red` verhält sich wie bei Groq: Lokal falls verfügbar, sonst Rohtext.

Migration bestehender Werte: `.auto` → Lokal (entspricht dem bisherigen Ist-Verhalten am ehesten), `.immerOpenAI` → Online/OpenAI. Werks-Default für Neuinstallationen bleibt Lokal (privacy-first); ein Hinweistext in den Einstellungen macht auf die Abschneide-Schwäche bei längeren Texten aufmerksam, ohne das Verhalten selbst zu ändern (der Bug wird hier nicht behoben, siehe `RewriteOutputValidator`/ADR 0012 für den bestehenden Schutzmechanismus).

Die Backend-Wahl gilt weiterhin global für alle drei Rewrite-Workflows (kein Pro-Workflow-Override), und die Online-Anbieter-Wahl bleibt mit der Glättung geteilt — eine Einstellung für „welcher Online-Anbieter", statt zwei unabhängige, die auseinanderlaufen können.

**Konsequenz:** `RewriteConsentCoordinator`, `RewriteConsentReason`, der zugehörige Dialog und `AppSettings.rewriteConsents` werden für Rewrite gegenstandslos und sind zu entfernen — es gibt keinen Laufzeitpfad mehr, der sie auslöst. `RewriteRouter` verliert den Local-first-Versuch als impliziten Ablauf und wird zu einer expliziten Verzweigung über die neue Backend-Wahl, strukturell näher an `OnlineSmoothing`/`LiveSmoothingBackend` als am bisherigen eigenen Muster. Wer künftig einen vierten Wert („Auto": bei zu langem Text automatisch von Lokal auf Online wechseln) ergänzt, tut das bewusst als Erweiterung von Achse A (Aus/Lokal/Online/Auto) — depriorisiert wegen der Datenschutzfrage einer stillen Lokal→Online-Eskalation, siehe die analoge, ebenfalls depriorisierte Option bei der Transkription („Online-Fallback-Einwilligung").
